Agent harness 是自己记忆、会话和摘要的 owner；Taskboard 只负责读取这些记录， 归一成统一的会话视图，做展示和整理。Kanban 是 Taskboard 的 WebUI 名称，不是独立产品或数据库。 Phase 1 不创建会话、不发消息、不恢复线程、不设置 goal，也不驱动下一 turn。

Phase 1 边界

显示、读取、整理是产品；驱动、恢复、审批、执行不是本阶段产品。

提供

  • 读取：发现、增量扫描、解析、去重、索引、source locator。
  • 展示：Inbox、Kanban、线程详情、turn 时间线、证据、搜索。
  • 整理：native summary 提取、确定性归并、SystemOne 进度判断与 Workstream overlay。
  • 人工 overlay：绑定、解绑、忽略、恢复、标签、注释、归档。

不提供

  • 不驱动：create thread、send message、cancel、resume、sample、fork、compact、goal。
  • 不自动推进：cron 触发 agent run、级联执行、automatic next action、自动 mark_done。
  • 不代答审批：不替用户批准 tool/permission，也不伪造 approval 结果。
  • 不写 native memory：不修复、不压缩、不改写、不删除 harness 自己的会话记录。

处置 模块 目标
复用 src/reader/*、src/store/*、src/views.ts、src/http.ts、web/src/* 保留读取、增量、索引、展示和来源定位；它们是 Phase 1 的主体。
重构 src/summary.ts、src/jev.ts、src/types.ts 把 summary 从 sample 写路径解耦；新增 SystemOne ProgressVerdict 与 Magpie provider；扩展 provenance/身份模型。

最重要的修正：Taskboard 不应该把 Codex 的 app-server 或 ACP agent 当成自己要实现的下游运行时。 它只读取 Harness 已经保存的记忆；能读到原生摘要就用原生摘要，进度语义则由默认经 Magpie 调用的 SystemOne 统一验证。 一旦需要 resume、sample、send 或 goal 才能拿到信息，就已经越过 Phase 1 的只读边界。
