# 代码审查标准

本文件保存 taskboard 仓库特有的审查规则。通用方法使用 `code-review` Skill；异源复审使用 `ocr`。

## Record 动态键分发

`Record<string, ...>` 以外部值动态索引并用于分发或查找时，必须用 `Object.hasOwn` 守卫，或构建时使用 `Object.create(null)`。

原型链键（`constructor`、`__proto__`、`toString`）不得被当作有效业务键。TypeScript 不检查这个运行时边界。

## 清单对齐测试

同一清单、枚举或键集合出现在第二个位置时，必须增加跨位置对齐测试，证明常量、独立真值和消费位置一致。

只比较 union 不够。清单经过合并或单表化后，还要逐命令、逐消费方核对原子集没有丢失；不带目标参数的 parity 用例也会漏掉单个入口丢条目。

## 补测试要证明能红

为既有行为补直测且测试直接通过时，先做变异验证：破坏被测接线，确认测试变红，再恢复并复查 diff。

绿色测试只证明当前命令通过，不证明测试能发现回归。文本级恢复脚本可能误改模板字符串中的内容，恢复后必须检查 diff。

## 镜像与重复先核对语义

发现两处清单或定义不一致时，先查注释、提交说明和 ADR，确认差异是否有意。

有意保留的子集是防护，不是自动视为漂移。只有确认语义相同后才判为重复债。

## 审查工具建议不照抄

`ocr` 或其它审查工具给出的建议代码，先验证可编译、行为等价，再落位。

建议 diff 无法直接应用时，按语义等价改写，并在处置记录说明偏差。
